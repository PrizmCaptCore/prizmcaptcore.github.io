Overview

제품 하나로 현대 AI 엔지니어링의 전 계층을

Relay는 회의를 캡처해 실시간 전사하고, 그 전사를 구조화된 검색 가능한 지식(진행 중 요약, 추출된 결정, 액션 아이템)으로 바꿉니다 — 네이티브 데스크톱 앱과 웹 플랫폼 양쪽에서.

흥미로운 지점은 범위의 폭입니다. 같은 제품이 클라이언트의 실시간 오디오 시스템, 클라우드의 비용 튜닝 GPU 서빙, 저자원 언어를 위한 전이학습 ASR 모델, 프로덕션 웹 백엔드, 그리고 비정형 발화를 구조화하는 추론 계층을 모두 필요로 했고, 그 전부를 제가 맡았습니다. 아래는 그 아키텍처와 의사결정이며 — 제품/조직명·인프라 좌표·자격증명·비용 수치·고객 데이터는 제거했습니다.

01

실시간 데스크톱 전사

Tauri (Rust) · Next.js · 오디오 DSP · 스트리밍 ASR

회의를 녹음하며 실시간 전사하는 네이티브 앱. 핵심 난제는 지연 vs 정확도라, 파이프라인을 하이브리드로 설계했습니다 — 로컬 CTC 모델이 왕복 없이 partial 을, 더 강한 클라우드 모델이 발화별 최종 전사를 냅니다.

  • 하이브리드 STT — 온디바이스 partial + 클라우드 final 을 화해시켜 보이는 텍스트가 뒤로 덜컥 되돌아가지 않게.
  • 채널 분리 — 마이크와 시스템 오디오를 독립 캡처·화자분리해 공유 콜에서도 "나 vs 상대"가 정확.
  • VAD + 노이즈 억제를 인식기 앞단에 두어 낭비 추론과 헛 partial 감소.
  • 단일 바이너리 배포 — 모델·ONNX 런타임을 빌드 시 번들, 테스터는 설치만.

02

비용 튜닝 GPU 추론 플릿

vLLM · serverless GPU · LLMOps · 배포 엔지니어링

요약/인텐트·임베딩·번역 세 서비스를 vLLM 으로 서빙. 질문은 "돌아가느냐"가 아니라 "idle 일 때 얼마가 나가느냐" 였습니다 — 워크로드마다 duty cycle 이 극단적으로 달라서, 그 차이를 토폴로지에 직접 새겼습니다.

요약 / 인텐트
회의 중 실시간, 사용자가 대기.
min 1 · always-on
임베딩
sparse 배치 동기화, idle ~99%.
min 0 · scale-to-zero
번역
사용 빈도 의존, duty cycle 로 결정.
min 0–1
  • 지연을 체감하는 곳에만 과금 — 실시간 대기 서비스만 always-on, 나머지는 idle 시 GPU 반납.
  • Zero-rebuild 배포 — ~80GB 베이스라 시작 시 최신 코드를 pull 해 in-place 핫리로드, 실패 시 baked 이미지로 fallback.
  • 가중치 이미지 baking 으로 scale-to-zero cold start 를 분이 아닌 수십 초로.
  • 계층 인증 — 플랫폼 API Key 1차 + 회전 내부 키 2차(무중단 회전 grace window).
  • Matryoshka 절단 — 같은 벡터를 클라이언트에서 앞 N차원만 잘라 온디바이스 인덱스 최대 4배 축소.

03

커스텀 한국어 ASR (인코더 전이)

NeMo · PyTorch Lightning · 전이학습 · speech

기성 인식이 한국어 회의엔 부족해서 직접 학습했습니다. 처음부터가 아니라 사전학습 영어 encoder 를 이식해 음향 표현을 공짜로 얻고, 데이터 예산은 언어 계층에 몰았습니다.

  • 2단계 스케줄 — stage 1 encoder 고정(decoder + 새 tokenizer 만), stage 2 전체 unfreeze 후 낮은 LR fine-tune.
  • 한국어 SentencePiece BPE 토크나이저, CTC head 에 맞춘 vocab 크기.
  • 상업적 사용 가능 공개 코퍼스(Common Voice / FLEURS)를 단일 manifest 로 정규화.
  • Loanword 보존을 명시적 eval 게이트로 — 영어 용어가 한글 음차되지 않게.
NVIDIA NeMoPyTorch LightningSentencePieceCTCMixed precision
04

프로덕션 웹 플랫폼 & 백엔드

Django · DRF · Celery · React · AWS ECS / CloudFront

계정·워크스페이스·회의 히스토리·B2B 프로비저닝·어드민을 담당. 동시에 server-rendered 템플릿 → API+SPA 마이그레이션 중이었고, 이런 전환은 뭔가가 막지 않으면 조용히 되돌아갑니다.

  • 아키텍처 테스트 = fitness function — 레거시 템플릿 표면을 동결하고 HTML 렌더 새 페이지 추가를 금지해 API-only 경계 유지.
  • CDN/컴퓨트 분리를 로컬에서 리허설 — SPA 를 Django 와 별도 서빙해 프로덕션 분리를 흉내.
  • 프로덕션과 같은 async — Celery worker+beat 를 로컬에서도 실제 프로세스로.
  • 멱등 B2B 일괄 프로비저닝 — CSV, dry-run, 팀 바인딩, 재설정 링크 export.
DjangoDRFCeleryPostgreSQLRedisReact/ViteAWS ECSCloudFront
05

회의 지식그래프 엔진

Applied LLM systems · 그래프 모델링 · Python

전사를 쓸모 있게 만드는 계층. 대화가 스트리밍되는 동안 사건·결정·액션·이슈의 증분 그래프를 만들고, 새 결정이 과거 결정을 뒤집는(reversal) 순간을 잡습니다. 원칙은 LLM 은 좁은 판단만, 구조는 결정론적 규칙.

  • LLM 은 좁은 판단, 코드가 구조 — 모델은 분류·매칭만, 새 사건으로 끊을지는 결정론적 cut 규칙.
  • 값싼 기계적 prewhere — 토큰 겹침으로 후보를 줄여 히스토리가 커져도 LLM 비용 상한 유지.
  • 근거 있는 인과만 — caused-by 는 명시 단서에서만(환각 링크 방지).
  • reversal 자동 감지 — "말 바꾼 지점"을 자동 표면화.
PythonLLM orchestrationGraph modelDeterministic rules
06

인프라 & 딜리버리

IaC · CI/CD · 컨테이너 레지스트리

연결 조직 — 재현 가능한 IaC, 그리고 서비스 이미지를 QEMU 없이 x86 러너에서 빌드·배포하는 CI. 경로 필터로 바뀐 서비스만 재빌드합니다.

  • Infrastructure as Code 로 재현·리뷰 가능한 환경 변경.
  • Path-filtered CI — 바뀐 서비스만 재빌드, 큰 ML 이미지는 순차 빌드로 디스크 관리.
  • 시크릿을 레이어 밖으로 — 모델 토큰을 BuildKit secret 으로 주입.

실용적 AI

판단은 LLM, 구조는 결정론적 규칙 — 모든 걸 모델에 맡기기보다 신뢰성 우선.

익명화 안내. 제품·조직명, 인프라 식별자(endpoint, 이미지 레지스트리, IP 주소), 자격증명, 비용 수치, 고객 데이터는 제거·일반화했습니다. "Relay" 는 실제 제품명을 대신하는 자리표시자이며, 공개 모델·프레임워크명은 기밀이 아니라 기술적 사실을 보여주므로 그대로 두었습니다.
